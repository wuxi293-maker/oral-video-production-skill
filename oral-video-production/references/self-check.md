# 交付前自检

> 这是硬门槛：未通过不得发 CDN 链接，也不得覆盖本地成片。  
> 每次制作完成后完整跑一遍；修改后重跑，不能只看上一版。

## 0. 自检顺序

1. 技术检查：`python3 scripts/qc_video.py <final.mp4> --json-out qc_report.json`
2. 字幕条检查：`python3 scripts/qc_captions.py <final.mp4> --json-out caption_qc.json --contact-sheet caption_qc.jpg`
3. 素材—音频对应：逐句核对 + 抽帧。
4. 素材异常：逐镜看首帧/中帧/尾帧 + 连续帧。
5. 字幕闪动：逐次字幕切换看 3 帧 + 回看 `caption_qc.jpg`。
6. 抖音字幕/操作安全区：叠安全区参考图 + 发布预览。
7. 写结论：通过 / 不通过 / 原因 / 修改。

## 1. 素材使用是否对应音频内容

### 做法

建一张“台词—素材对应表”，逐句填：

| 句号 | 起止秒 | 台词 | 关键词 | 素材 | 画面内容 | 对应 | 偏差 |
|---|---|---|---|---|---|---|---|
| 1 | 0.00–3.02 | 一百年前，我们求福特… | 一百年前/福特 | sun_letter | 孙中山致福特信函 | 是 | 0.1s |

- 每句至少抽 1 帧；关键数字、地点、人物、产品再抽首尾 2 帧。
- 在切点前后 0.5 秒各看一帧，确认画面与词同步。
- 有口播时，以词级时间戳为准；没有词级时间戳时，以人声波形/听感为准。

### 通过标准

- 画面语义与台词一致；不出现“说 A 放 B”。
- 关键数字、地点、人物、产品与素材一致。
- 镜头切换不早于/晚于对应词超过约 0.3 秒。
- 不出现“台词已经讲完，画面还在上一个话题”的拖尾。

### 常见失败

- 台词说“密歇根下线”，画面还是 1924 年档案图。
- 台词说“匈牙利建厂”，画面放的是印尼矿山。
- 台词说“首批电芯”，画面是电池包成品。
- 画面切早了，关键词还没出口；或切晚了，下一句已经开始。

## 2. 素材是否有问题

### 做法

每个镜头看：

- 首帧、中帧、尾帧；
- 连续 5–10 帧看闪烁/抖动/花屏；
- 原素材与成片各看一次（排除渲染问题）。

### 通过标准

- 无黑帧、冻结帧、重复帧、解码花屏、闪白、闪黑。
- 无低清放大、拉伸变形、主体裁切、错误水印/角标。
- 横竖屏正确；帧率 30fps CFR；无插帧鬼影/撕裂。
- 色彩/曝光正常；夜景不糊，产品颜色不失真。
- 素材不重复；同一角度只出现一次。
- 素材来源/授权可追溯。

### 重点检查

- 人物脸部、手部、产品 logo 是否被裁。
- 产品电芯/电池包的正负极、结构是否被镜像或拉伸。
- 官方图是否有第三方水印、头条/公众号角标。
- 视频素材是否有平台 UI、字幕烧录、时间码。
- 慢动作/延时素材是否被误当正常速度。

## 3. 字幕是否闪动

### 做法

在每次字幕切换点：

- 看切换前 1 帧、切换帧、切换后 1 帧；
- 连续播放该段 2–3 秒；
- 放大字幕条区域看边缘。

**先跑脚本**：

```bash
python3 scripts/qc_captions.py <final.mp4> \
  --json-out caption_qc.json \
  --contact-sheet caption_qc.jpg
```

脚本会逐帧计算字幕条区域的边缘能量，找出“文字接近空白”的帧并输出联系表。默认区域是 TP02 字幕条；TP01 没有底部字幕条，不跑或改用 `--region`。TP02 样例 v1/v2 的 `Subtitle` 对每条字幕做 4 帧淡入、3 帧淡出，每个句界都出现 1 帧空白；`qc_captions.py` 在 v2 检出 20 段（19 个句界 + 末帧）。新片不要复刻，底部整句字幕改为瞬时换字。

### 通过标准

- 字幕底板常驻，只换文字；不出现一帧空白。
- 底部整句字幕瞬时换字，不做逐句淡出/淡入；入场动画只给素材内重点提示。
- 不出现旧字+新字叠加、双行跳变、文字上下跳动。
- 同一句可以跨镜头；字幕条保持常驻，不因切镜重建或闪空；不出现半句被切掉。
- 文字不超出底板；标点不孤行；字号不忽大忽小。
- 无错别字、ASR 误识、重复字。
- 重点提示入场/出场不遮住底部字幕。

### 常见原因

- 逐句挂载/卸载字幕组件 → 切换帧空一帧；改为常驻底板。
- 字幕文字长度变化导致换行/居中跳动；固定行高、最大宽度，超长自动缩字号。
- 字幕条背景透明度逐帧变化 → 看起来闪；背景保持恒定。
- 重点提示和底部字幕同时入场 → 两层文字抢戏；错开 3–5 帧。

## 4. 符不符合抖音字幕和操作安全区

> 下面是 1080×1920 的保守参考，不是平台官方规范；发布前必须用抖音预览再核对一次。

| 区域 | 建议避让 | 说明 |
|---|---|---|
| 顶部 | `y < 120px` | 搜索/导航/状态栏，不放关键标题 |
| 底部 | `y > 1600px` | 文案、话题、按钮区，不放字幕/关键数据 |
| 右侧 | `x > 960px` | 点赞/评论/分享按钮，不放关键字幕/数据 |
| 左侧 | `x < 60px` | 边缘裁切，不放关键信息 |

### 通过标准

- 底部字幕在 `y ≤ 1600`，距底边至少约 300px。
- 标题、关键数据、重点提示不被右侧 120px / 顶部 120px / 底部 300px 覆盖。
- TP02 字幕条在 `y 1132–1226`，天然在安全区；仍需检查重点提示是否右移过多。
- TP01 信息卡在 `bottom 300`（`top 1282`），已在保守安全区内；发布前仍需叠图核对实际 UI。
- 发布预览里，字幕不被文案、按钮、进度条遮挡；关键画面不被裁切。

### 做法

1. 用 `assets/douyin-safe-area-1080x1920.svg` 叠在关键帧上检查。
2. 在抖音发布页预览，确认 UI 实际覆盖范围。
3. 若平台 UI 变化，以实际预览为准，不硬套旧数值。

## 5. 技术检查

`scripts/qc_video.py` 会检查：

- 时长、分辨率、帧率、视频码率、音频流；
- 黑帧段（`blackdetect`）；
- 冻结段（`freezedetect`）；
- 音量均值/峰值（`volumedetect`）；
- 输出 `qc_report.json`。

注意：

- `freezedetect` 对慢速 Ken Burns 静图可能误报；看报告后回帧确认，不直接判死。
- 技术通过 ≠ 视觉通过；第 1–4 项必须人工看。
- 任何硬失败（黑帧、无音频、分辨率/帧率错误）必须修后重渲。

## 7. 不通过时怎么修

| 问题 | 修法 |
|---|---|
| 素材与台词不对应 | 换素材或调整镜头起止；必要时重排该句 |
| 素材黑帧/冻结/花屏 | 换源、重转码、裁掉坏段；不要靠调色掩盖 |
| 素材低清/拉伸 | 换高清源；按原比例裁切，不硬拉 |
| 字幕闪空 | 字幕底板常驻，只换文字；固定行高/宽度 |
| 字幕跳行 | 限制最大字数，超长缩字号；可跨镜，但不为卡镜头拆句 |
| 字幕被 UI 遮 | 整体上移；右侧留 120px；底部留 300px |
| 重点提示遮主体 | 换位置/缩小/延后入场；同时只留一条 |
| 音画不同步 | 以词级时间戳重排；检查 `offset` 与 `start` |
