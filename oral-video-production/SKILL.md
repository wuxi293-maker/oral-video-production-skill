# 口播视频制作

## 硬规则

- **制作完成后必须自检**：素材使用是否对应音频内容、素材是否有问题、字幕是否闪动、符不符合抖音字幕和操作安全区；未通过不得发 CDN 链接。
- **口播不固定单镜时长**：按脚本语义与语音节奏切，不套“每镜 3 秒”。
- **硬切为主**：转场只放在章节/时空跳点，不逐切点堆；可用多种样式，但每个切点只选一种。
- **字幕底板常驻**：只换文字，不逐句挂载/卸载，避免闪空。
- **先发 CDN 链接，用户确认后再落本地**。
- **结尾卡不保留左下角账号/栏目文字**，只留必要信息。

## 0. 先选模板

| 编号 | 名称 | 用途 | 关键特征 |
|---|---|---|---|
| **TP02** | 红米口播版 | 口播、访谈、故事、前后对比 | 红底细白框、米色大卡、黑色媒体窗、红字幕条、蓝粉笔刷标题 |
| **TP01** | 蓝图资讯版 | 资讯、数据、公告、证据型内容 | 深色蓝图底、黄绿强调、底部纸张信息卡 |

- 有口播、人物、故事、前后对比 → 默认 **TP02**。
- 无口播或弱口播的资讯、数据、公告 → **TP01**。
- 需要完整坐标、字段和样片，读：
  - `references/tp02-red-cream-oral.md`
  - `references/tp01-blueprint-news.md`

## 1. 接任务与读脚本

从用户输入提取：

1. **脚本来源**：飞书文档链接、章节/标题；只读指定段落。
2. **模板**：TP01 / TP02；未指定时按内容判断。
3. **配音**：人声文件、是否需要清气口/提速。
4. **特殊要求**：标题行数、素材方向、封面、平台、时长。
5. **素材**：用户给的链接或文件；缺的由助手检索、截图、下载并保存。

不改事实、数字、日期、人名、引语。脚本标题是片内唯一标题，全片固定。

## 2. 处理音频，先定全片时间轴

口播片以人声为主时间轴，不先排画面。

1. 用 `silencedetect` 找气口/停顿，压到 0.10–0.16 秒。
2. 按语速需要做整体提速，常用 `atempo=1.2`；保持音高。
3. 加 `highpass=52`、`lowpass=14500`、`alimiter=0.95`，导出 48kHz 单声道 WAV。
4. 用 faster-whisper 或同等工具做词级时间戳；ASR 误识按脚本原文校正。
5. 成片长度跟处理后的人声，不为了凑整秒拉长镜头。

详细命令与参数见 `references/workflow.md`。

## 3. 排镜头与素材

- **不固定单镜 3 秒**。口播按语义与停顿切，资讯按信息点切。
- 每个镜头写清：起止帧、素材、景别/动作、对应台词、转场、重点提示。
- 图片与实拍混用；同一素材不重复，不用带角标/水印的截图。
- 实拍统一转 30fps CFR，用 `setpts` 对齐源帧，不做运动插帧。
- 默认硬切；转场只放在章节/时空跳点，不逐切点堆。
- TP02 常用 7 种转场：fade、slideLeft、slideUp、wipeLeft、wipeUp、push、blur；每个切点只选一种。
- 素材内重点提示只做短标签、日期、结论；不与底部整句字幕重复。

## 4. 搭 Remotion 工程

- 画布：1080×1920，30fps，目标 12Mbps，AAC 192k。
- Composition 的 `durationInFrames` 取最后一个镜头的 `end`，不按固定镜头数×90。
- 镜头、转场、重点提示、字幕全部数据化；不要把整片写死在一个组件里。
- 视频用 `OffthreadVideo` 逐帧取帧；图片用 `Img` 加 Ken Burns。
- 字幕条常驻渲染，只换文字；不要逐句挂载/卸载，也不要做整句透明度淡入淡出，否则容易闪空。
- 音效用 `Sequence` 挂在段落节点，不逐镜添加。
- 代码骨架与转场/字幕实现见 `references/remotion-patterns.md`。

## 5. 字幕与信息层

**底部整句字幕**

- 红条/底板常驻，只换文字。
- 一句字幕可以跨镜头；按词级时间戳切，不为了卡镜头把一句话拆断。
- 同一时间只显示一条，不叠字、不空帧。

**素材内重点提示**

- 三种样式：`tag`、`date`、`statement`。
- 四种入场：`mask`、`pop`、`slide`、`blur`。
- 同时最多一条；不遮挡人脸、产品主体、关键数据。
- 时长与对应词对齐，通常 1.5–4 秒。

## 6. 声音

- BGM 用抖音热门曲，不用 AI 生成；增益约 `0.20`。
- 音效只挂段落起点、数据卡、结尾等关键节点；不逐镜添加，不硬套“10 处/100 秒”的密度。
- 人声清晰优先；BGM 不压字，音效不刺耳，不爆音、不削波。
- 样片如用免版税曲临时铺底，交付说明里写清来源；正式版按用户要求换抖音热门曲。

## 7. 渲染

```bash
npx remotion render src/index.ts OralVideo out/master.mp4 \
  --codec=h264 --pixel-format=yuv420p \
  --video-bitrate=12M --audio-codec=aac --audio-bitrate=192k \
  --concurrency=4
```

- 先出高质量母版，再确认码率/时长/分辨率。
- 封面从首帧或指定帧裁 3:4（1080×1440），关键标题与主体落在安全区。
- 渲染后不要直接交付，先进入第 8 步自检。

## 8. 交付前自检（硬门槛）

**每次制作完成后必须做一次完整自检；未通过不得发 CDN 链接。**

先运行技术检查：

```bash
python3 scripts/qc_video.py <final.mp4> \
  --expected-duration <秒> \
  --json-out qc_report.json

python3 scripts/qc_captions.py <final.mp4> \
  --json-out caption_qc.json \
  --contact-sheet caption_qc.jpg
```

`qc_captions.py` 会逐帧比较字幕条区域的边缘能量，找出“文字接近空白”的帧，并输出联系表。默认区域是 TP02 字幕条；TP01 没有底部字幕条，不跑或改用 `--region`。TP02 样例 v1/v2 在每个句界都有 1 帧空白，属于已知缺陷，不能当合格样例复刻。

再按 `references/self-check.md` 做人工/逐帧检查，至少覆盖四项：

1. **素材使用是否对应音频内容**
   - 每句台词对应的画面语义是否正确；不出现“说 A 放 B”。
   - 关键数字、地点、人物、产品与素材一致。
   - 镜头切换不早于/晚于对应词超过约 0.3 秒。

2. **素材是否有问题**
   - 无黑帧、冻结帧、重复帧、解码花屏、闪烁、抖动。
   - 无低清放大、拉伸变形、主体裁切、错误水印/角标。
   - 横竖屏、帧率、色彩、曝光正常；不出现插帧伪影。

3. **字幕是否闪动**
   - 字幕底板常驻，切换时只换文字，不出现空白帧/双行叠加/跳行。
   - 同一句可以跨镜头；字幕条保持常驻，不因切镜重建或闪空；不出现一帧旧字、一帧新字。
   - 无错别字、ASR 误识、标点溢出、文字超出底板。
   - `qc_captions.py` 报出的低文字帧必须逐帧回看。底部整句字幕不要做逐句淡出/淡入；只有素材内重点提示才做入场动画。

4. **符不符合抖音字幕和操作安全区**
   - 底部字幕保持在保守安全区内：1080×1920 下建议 `y ≤ 1600`，距底边至少约 300px。
   - 右侧约 120px 不放关键字幕/数据；顶部约 120px 不放关键标题；底部约 300px 不放关键信息。
   - 用抖音发布预览再核对一次；平台 UI 会变，以实际预览为准。
   - TP01 信息卡已在 `bottom 300`（`top 1282`），发布前仍用抖音预览核对；平台 UI 变化时再整体上移。

自检结果写入 `qc_report.json` 或 `qc_notes.md`：逐项写“通过/不通过/原因/修改”。不通过就修、重渲染、再检，直到全部通过。

## 9. 交付

- 先在对话里发 CDN 的 mp4 链接；用户确认后才保存/替换本地文件。
- 本地目录：`日期_脚本名/`；视频名用脚本名；版本从 `v1` 起，保留 v1–vN。
- 封面 3:4；需要时同时发封面链接。
- 交付说明写清：模板编号、时长、分辨率、码率、BGM 来源、自检结果。

## 10. 扩展模板

- 当前模板号：TP01、TP02；TP03–TP05 预留。
- 新模板先跑真实样片，再启用编号；编号不复用，退役只改状态。
- 只复用共用底座，不整段复制旧模板代码。

## 常见坑

- 字幕逐句挂载/卸载 → 切换帧闪空；改为常驻底板只换文字。
- 每个切点都加转场 → 节奏发软；改为硬切为主，章节点才转。
- 先排画面再配音 → 素材与台词错位；先定人声时间轴。
- 用固定 3 秒套口播 → 语句被切断；按语音与语义切。
- 只看技术指标不看画面 → 黑帧/冻结/错素材漏检；技术检查 + 逐帧自检都要做。
- 底部信息卡贴底 → 被抖音 UI 遮挡；整体上移或把关键信息放上半区。
